## 2. 현재 작업 상태

아직 코드 수정은 시작하지 않았다.

기존 기능을 최대한 유지하면서 확장하는 방식으로 구현한다.

프로젝트의 기존 핵심 흐름은 대략 다음과 같다.

X-ray 이미지\
→ AI/이미지 분석을 통한 척추 측정\
→ 척추체 높이 및 압박률 계산\
→ 결과 출력 및 저장

기존 측정 기능을 삭제하거나 전면 재작성하지 않는다.

## 3. 이번 구현의 최종 목표

현재의 X-ray 압박률 계산 기능에 다음 기능을 연결한다.

X-ray 측정\
→ 압박률 계산\
→ 공식 장해 기준 판독\
→ 장해등급 후보 생성\
→ 국가법령정보 OPEN API 검색\
→ 관련 법령 및 판례 자동 검색\
→ 실제 판례의 측정값/판단과 현재 결과 비교

최종적으로 사용자가 한 번 측정하면 아래와 같은 결과를 얻도록 한다.

예:

- 측정 부위: L2
- AI 측정 압박률: 25.4%
- 적용 기준: 산재
- 장해 분류 후보: 중등도의 변형장해
- 장해등급 후보: 제12급
- 관련 법령
- 관련 조문/별표
- 관련 판례 목록
- 판례 사건번호
- 판례 선고일
- 판례에서 사용된 압박률
- 법원이 인정한 결과
- 현재 AI 측정값과 판례 측정값의 차이

주의:

AI가 임의로 최종 법적 장해등급을 결정하는 구조가 아니라,

**공식 기준에 따른 "등급 후보/판독 결과"를 제시하는 구조**

로 만든다.

# 4. 국가법령정보 OPEN API

참고 사이트:

[https://open.law.go.kr/LSO/openApi/openApiManual.do](https://open.law.go.kr/LSO/openApi/openApiManual.do)

국가법령정보 OPEN API를 사용한다.

주요 API 목적은 다음 두 가지이다.

### 법령

공식 장해평가 기준, 시행령, 시행규칙, 별표 등을 검색 및 조회한다.

예상 흐름:

lawSearch.do\
target=law

→ 법령 검색

lawService.do\
target=law

→ 선택된 법령의 상세 내용 조회

### 판례

장해율, 척추 압박률, 장해등급 등 관련 판례를 자동 검색한다.

예상 흐름:

lawSearch.do\
target=prec\
search=2

→ 판례 본문검색

판례 ID 획득

→

lawService.do\
target=prec\
ID=판례ID

→ 판례 전문 조회

# 5. OC 인증값 처리

지금은 국가법령정보 OPEN API의 OC 인증값을 제공하지 않는다.

따라서 코드부터 완성한다.

인증값은 절대로 소스코드에 직접 작성하지 않는다.

예:

LAW_API_OC

라는 환경변수를 사용한다.

Python에서는 예를 들어:
```
import os

LAW_API_OC = os.environ.get("LAW_API_OC")
```

방식으로 처리한다.

OC가 없을 때 프로그램 전체가 죽지 않도록 한다.

예:

- X-ray 측정은 정상 진행
- 장해 기준 판독도 정상 진행
- 판례 API 부분만 "API 인증값 미설정" 상태로 반환

나중에 사용자가 OC 인증값을 넣으면 별도의 코드 변경 없이 바로 판례 검색이 작동해야 한다.

# 7. law_api.py 역할

국가법령정보 OPEN API 통신만 담당한다.

최소 기능:
```
search_law()
get_law()

search_precedents()
get_precedent()
```

예:
```
search_precedents(
    query="척추체 압박률 장해등급",
    display=20
)
```

검색 결과에서 다음 정보를 정규화해서 반환한다.

- 판례일련번호
- 사건명
- 사건번호
- 선고일자
- 법원명
- 판결유형
- 판시사항
- 판결요지
- 판례내용
- 참조조문

API 응답 구조가 1건/여러 건일 때 dict/list 형태가 달라질 가능성도 방어한다.

HTTP 오류, JSON 오류, API 인증 오류에 대한 예외 처리도 넣는다.

# 8. rating_engine.py 역할

AI가 아닌 코드 기반 규칙 엔진을 만든다.

입력:
```
압박률
측정 부위
적용 평가기준
추가 측정값
```

출력 예:
```
{
  "standard": "sanjae",
  "body_part": "spine",
  "compression_rate": 25.4,
  "category": "중등도의 변형장해",
  "grade_candidate": "제12급",
  "is_final_legal_judgment": false
}
```

중요:

등급 계산 규칙은 공식 법령/별표를 근거로 구현한다.

LLM이 숫자를 보고 임의 판단하지 않는다.

# 10. 측정 방법 관련 중요사항

현재 프로젝트가 척추체의 전방 높이 중심으로 계산하고 있다면 공식 기준과 정확히 일치하는지 검토한다.

가능하면 측정 지점을 다음으로 확장할 수 있도록 설계한다.

- Anterior height
- Middle height
- Posterior height

각각에 대해 압박률을 구하고 공식 기준에서 요구하는 방식에 맞게 최종 압박률을 산출한다.

단,

**근거 확인 없이 기존 계산식을 임의로 변경하지 않는다.**

기존 M1/M2/M3/M4 계산 결과도 보존한다.

법적 평가용 계산값은 별도 변수로 분리한다.

예:
```
research_M1
research_M2
research_M3
research_M4

legal_compression_rate
```

# 11. 자동 판례 검색 로직

장해등급 후보가 나오면 해당 결과를 기반으로 판례 검색어를 자동 생성한다.

예:

압박률 25.4%\
산재\
제12급 후보

↓

검색어:
```
척추체 압박률 장해등급
척추 압박률 제12급
장해등급결정처분취소 척추체 압박률
요추 압박골절 장해등급
```

여러 검색 결과를 합친 뒤 판례일련번호 기준으로 중복 제거한다.

# 12. 판례 AI 분석

판례 전문을 가져온 뒤 필요한 정보만 구조화한다.

예:
```
{
  "case_number": "",
  "court": "",
  "decision_date": "",
  "body_part": "",
  "diagnosis": "",
  "compression_rate": null,
  "grade": "",
  "doctor_opinion": "",
  "court_opinion": "",
  "legal_basis": [],
  "measurement_values": [],
  "usable_for_validation": false
}
```

단,

AI가 판례에 없는 숫자나 사실을 만들어내지 않도록 한다.

판례 원문에서 직접 근거를 찾지 못하면 null 또는 "확인 불가"로 처리한다.

가능하면 추출된 값이 나온 원문 문장도 같이 보존한다.

# 14. 중요한 개발 원칙

### 기존 기능을 망가뜨리지 않는다.

새 기능은 가능한 한 모듈 형태로 추가한다.

### API와 판정 로직을 분리한다.

`law_api.py`

\= 법령/판례 데이터 수집

`rating_engine.py`

\= 장해 기준 계산

AI

\= 판례 텍스트 구조화/요약

역할을 섞지 않는다.

### API 인증값을 GitHub에 올리지 않는다.

`.env` 또는 환경변수를 사용한다.

필요하면 `.gitignore`도 수정한다.

### 공식 근거가 없는 기준값을 임의로 작성하지 않는다.

공식 법령/시행규칙/별표에서 확인한 기준만 코드에 넣는다.

### 기존 코드 변경은 최소화한다.

가능하면 기존 `run_measure.py`의 측정 완료 이후에 다음 흐름을 추가한다.
```
measurement_result
    ↓
rating_engine
    ↓
law_api
    ↓
precedent_analysis
    ↓
save_report
```

# 16. 다음 대화에서 작업 시작 시 지시

이 문서를 받은 다음 대화에서는 먼저 현재 GitHub 저장소의 실제 파일 구조와 코드를 확인한다.

그다음 위 설계와 실제 코드가 충돌하는 부분이 있는지 확인하고,

**현재 기능을 유지하면서 최소 변경으로 구현한다.**

코드를 임의로 갈아엎지 않는다.

필요한 파일을 추가하고 기존 파일에는 연결부만 최소 수정한다.

구현 완료 후에는 반드시 다음을 확인한다.

1. 기존 X-ray 측정 기능 정상 동작
2. OC가 없는 상태에서도 프로그램 정상 동작
3. 장해 기준 판독 기능 정상 동작
4. OC 미설정 상태가 명확하게 표시됨
5. 추후 `LAW_API_OC`만 설정하면 판례 검색 가능
6. API 오류가 나도 측정 기능은 중단되지 않음
7. 결과 JSON 저장 가능
8. 공식 기준 출처를 코드 주석 또는 데이터 파일에 기록
9. 비밀키가 GitHub에 포함되지 않음
10. README에 실행 방법과 OC 설정 방법 기록

최종 목표는 단순 압박률 계산기가 아니라,

**"X-ray 측정값 → 공식 장해 기준 → 관련 법령 → 실제 국내 판례"를 하나의 흐름으로 연결하는 AI 장해평가 보조 프로토타입**

을 만드는 것이다.
